Revin Onsite Prep Plan

2-hour onsite with lead engineer. Practical implementation prep, not LeetCode.

Sections

LangGraph (highest priority)

This is their core agent framework. The listing says "build and evolve LangGraph workflows that handle SMS and voice conversations." Be comfortable building a graph, adding conditional edges, and explaining how state flows through nodes.

Start here

  • LangGraph Overview — what it is, why it exists, how it differs from LangChain
  • Quickstart — build a calculator agent with StateGraph. Both Graph API and Functional API patterns
  • Workflows and Agents — tool-augmented agents, conditional routing, the ReAct pattern

Key concepts to know

  • StateGraph, MessagesState, START, END
  • Nodes are functions that receive state and return updates
  • Conditional edges route based on state (e.g., did the LLM make a tool call?)
  • add_node(), add_edge(), add_conditional_edges(), compile()
  • create_react_agent() for quick prototyping (prebuilt ReAct loop)
  • Human-in-the-loop patterns (relevant to Revin's "humans in the loop where it matters")

Go deeper

  • LangGraph v1.0 ReAct Agent Tutorial — uses the stable v1.0 API (October 2025+), not the deprecated v0.x patterns most tutorials still show
  • LangGraph examples on GitHub — multi-agent, tool calling, memory, streaming

What to build

Build a small agent that takes a customer message, classifies intent (book appointment, cancel, reschedule, general question), and routes to different handler nodes. This directly mirrors what Revin's agents do. Add a conditional edge that escalates to a human node when confidence is low.

LiveKit + OpenAI Realtime (high priority)

The listing confirms "Partner with the voice team on real-time agent behavior (LiveKit + OpenAI Realtime)." You already have OpenAI Realtime experience from Notes AI. LiveKit is the transport layer that connects the Realtime API to actual phone calls.

Start here

  • LiveKit Voice AI Quickstart — build and deploy a voice assistant in under 10 minutes
  • OpenAI Realtime API Plugin — how LiveKit wraps the OpenAI Realtime API specifically
  • Build Your First AI Voice Agent in Python — full tutorial: STT, LLM, TTS pipeline with LiveKit Agents

Key concepts to know

  • LiveKit Agents framework: AgentServer, AgentSession, Agent
  • Pipeline architecture: STT → LLM → TTS, streamed in real-time
  • VAD (Voice Activity Detection) and turn detection
  • How LiveKit connects to telephony (SIP trunking for inbound/outbound phone calls)
  • The difference between the pipeline approach (STT+LLM+TTS) and OpenAI Realtime (end-to-end multimodal)

What to build

Run the agent-starter-python template locally. Swap in OpenAI Realtime as the model. Talk to it. Understanding how the audio flows from microphone → LiveKit → OpenAI → LiveKit → speaker gives you the mental model for what Revin's voice agents do at scale.

FastAPI (medium priority)

Their backend. You know Express/Node.js well; FastAPI is the Python equivalent with type hints and auto-generated docs. The concepts transfer directly.

Start here

  • FastAPI Tutorial — official tutorial, covers path params, query params, request bodies, dependency injection, all with type hints
  • First Steps — hello world in 5 minutes

Key concepts to know

  • Path operations (@app.get(), @app.post())
  • Pydantic models for request/response validation
  • Dependency injection (Depends()) — this is how they likely handle auth and tenant scoping
  • Background tasks, middleware
  • async/await (FastAPI is async-first, similar to Node.js)

Node.js → FastAPI cheat sheet

  • express.Router() → APIRouter()
  • req.body → Pydantic model parameter
  • req.params.id → path parameter with type annotation
  • middleware() → @app.middleware("http") or Depends()
  • next() → dependency injection chain

Supabase Multi-Tenant Patterns (medium priority)

You already use Supabase. The new part is multi-tenancy with RLS and JWT-based access, where every query is account-scoped.

Start here

  • Supabase RLS Guide — how to write policies, common patterns
  • Supabase JWTs — how auth tokens carry tenant context

Key concepts to know

  • RLS policies that use auth.uid() or custom claims to scope queries
  • auth.jwt() ->> 'org_id' pattern for multi-tenant scoping
  • Why RLS matters: a bug in query scoping means one customer sees another's conversations
  • Service role key bypasses RLS (for admin/migration tasks only)

Eval Frameworks (medium priority)

The listing says "build the eval frameworks that catch agent regressions before they reach customers — we treat eval quality as a first-class engineering discipline." This is not just a nice-to-have; it's core to the role.

Start here

  • Langfuse Docs — open-source LLM observability: tracing, evals, prompt management. Listed as a bonus skill in the posting
  • LangSmith Docs — LangChain's tracing and eval platform. Also listed in the posting
  • Helicone Docs — LLM proxy for logging, monitoring, and rate limiting. Third option listed

Key concepts to know

  • Tracing: following a conversation through every LLM call, tool invocation, and decision point
  • Eval datasets: curated sets of inputs + expected outputs to catch regressions
  • Online vs. offline evaluation: real-time monitoring of live conversations vs. batch evaluation of historical data
  • LLM-as-judge patterns: using a second model to grade the first model's output
  • Metrics that matter for Revin: booking accuracy, intent classification precision, false promise rate, escalation rate

What to think about

If their agent books an appointment at 3 AM for a business that closes at 6 PM, how do you catch that before it reaches production? How do you build a regression suite from real conversation failures? How do you measure whether a new prompt version is better than the old one without A/B testing on live customers?

System Design Scenarios (for the conversation)

The 2-hour onsite will likely include some "how would you design this" discussion. Think through these scenarios in Revin's context.

Scenario 1: New customer onboarding

A new HVAC operator signs up. They use ServiceTitan. How do you set up a new tenant in the multi-tenant system? What data do you need from them (business hours, service areas, service catalog, qualification rules)? How do you configure the agent's behavior without writing new code?

Scenario 2: Agent makes a mistake

The agent booked a plumber for a service the customer doesn't offer. Walk through: how does the system detect this? How does the operator find out? What's the escalation path? How do you prevent it from happening again? (Hint: guardrails in the LangGraph workflow, eval regression test, maybe a validation node before the booking action.)

Scenario 3: Multi-channel conversation

A customer calls, gets an AI voice agent, but the call drops. The agent follows up via SMS. How do you maintain conversation state across channels? How does the LangGraph workflow handle the channel switch? What context carries over?

Scenario 4: Scaling from 5 customers to 50

What breaks first? Per-customer configuration that's currently hand-maintained? Eval coverage? Deployment pipeline? On-call burden? This ties directly to the platform-vs-custom question you already asked.
