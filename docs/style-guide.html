Documentation Style Guide

Shared document patterns for pages under basedin.nyc. This guide now reflects the real stylesheet used by pr-stats.

Integration

Documentation pages are no longer self-contained. They inherit the shared site stylesheet and the same body.pr surface used by the PR pages.

<meta name="darkreader-lock" />
<meta name="color-scheme" content="light dark" />
<link rel="stylesheet" href="../style.css?v=52940991">
<body class="pr">
  <main class="doc-page">
    ...
  </main>
</body>

Do not embed a separate <style> block. Do not add extra font imports. The shared stylesheet already owns typography, color tokens, cards, tables, notes, code blocks, and pills.

Prefer the shared components aggressively. If a document is just a stack of plain headings and paragraphs, it is probably under-using the system.

Pill Controls

Pills are the shared affordance for single-choice table controls. They live in .sort-pills, each control is a .sort-pill, and the current choice gets .active.

Do not use pills to hide ordinary document sections. If the page is a narrative draft, checklist, or reference doc, keep the content visible and use pills only as short jump navigation.

Actual uses in the site today:

  • pr-stats uses the same pill component to filter one table by status buckets such as shipped and open.
  • Section-heavy docs in /docs use the same pill styling as anchor navigation with short labels like Headline, About, and Skills.

View Toggle Pattern

<div class="landscape-row">
  <h2>Views</h2>
  <div class="sort-pills" id="view-pills">
    <button class="sort-pill active" data-view="summary" type="button">Summary</button>
    <button class="sort-pill" data-view="details" type="button">Details</button>
  </div>
</div>

<div class="section" data-view-panel="summary">...</div>
<div class="section" data-view-panel="details" hidden>...</div>
var pills = document.getElementById('view-pills');
pills.addEventListener('click', function (event) {
  var pill = event.target.closest('.sort-pill');
  if (!pill) return;
  var view = pill.getAttribute('data-view');
  pills.querySelectorAll('.sort-pill').forEach(function (node) {
    node.classList.toggle('active', node === pill);
  });
  document.querySelectorAll('[data-view-panel]').forEach(function (panel) {
    panel.hidden = panel.getAttribute('data-view-panel') !== view;
  });
});

Reserve hide/show view toggles for genuinely mutually exclusive content states. If a reader benefits from seeing all sections in one pass, do not use this pattern.

Pill Rules

  • One active pill only.
  • Place pills inside the same visual block as the content they control, usually a .landscape-row.
  • Prefer terse labels: sort key, status bucket, or view name.
  • Include counts in labels only when they are stable and helpful, as in pr-stats.
  • If you use real <button> elements for accessibility, keep the same .sort-pill class and toggle .active.
  • For document navigation, keep labels short and use the shared doc-nav.js script plus .doc-nav-target on the destination headings.
  • Do not duplicate section content into hidden pill panels just to make the pills work.
