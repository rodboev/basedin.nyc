Python for Node.js Developers

Learning resources for someone who thinks in JavaScript and needs to ship Python. Prioritized for AI/ML roles that use FastAPI, LangGraph, and typed Python.

Sections

Why Python is non-negotiable

Every AI/ML engineering role assumes Python fluency. LangGraph, LangChain, LiveKit Agents, FastAPI, and every major LLM framework are Python-first. Some have JS/TS ports, but the production codebases, the docs, the examples, and the hiring filters all assume Python. This isn't a preference; it's the water supply.

The good news: if you know JavaScript well, Python is a short hop. The concepts transfer directly. The syntax differences are small. The hard part is building muscle memory for the ecosystem (pip vs npm, pytest vs jest, Pydantic vs Zod, virtual environments vs node_modules).

Core Python (for someone who already programs)

Skip the "what is a variable" tutorials. These resources assume you can program and teach Python's specific idioms.

Start here

  • The Official Python Tutorial — surprisingly good. Skim chapters 1-4, read 5 (data structures), 6 (modules), 7 (I/O), 9 (classes) carefully
  • Learn Python in Y Minutes — single-page syntax reference for developers who already know another language. Bookmark this
  • How to write X in both Python 3 and JavaScript — side-by-side code blocks for every common pattern, organized by category. The ctrl+F reference
  • Real Python: Python vs JavaScript (video) — high-level comparison of the syntax, runtime, typing, and ecosystem differences

Key differences from JS

  • Indentation is syntax, not style. 4 spaces, no braces.
  • No let/const/var. Assignment creates the variable. Scope is function-level by default, not block-level.
  • None instead of null/undefined. There's only one "nothing" value.
  • Lists ([]) instead of arrays. Dicts ({}) instead of objects. Tuples (()) are immutable lists.
  • List comprehensions: [x * 2 for x in items if x > 0] replaces .filter().map() chains.
  • No semicolons. Newlines end statements.
  • import is file-based like Node, but there's no export: everything at module scope is importable.
  • Truthiness: empty collections, 0, "", and None are falsy. Everything else is truthy. Same instinct as JS minus the undefined edge cases.

Go deeper

  • Python Standard Library reference — the "batteries included" stdlib. Skim the table of contents to know what exists: pathlib, json, re, subprocess, collections, datetime, zoneinfo
  • Intermediate Python — free book covering generators, decorators, *args/**kwargs, context managers, and other Python-specific patterns you won't learn from JS analogies

Type hints and Pydantic

Python has types at runtime (everything is a typed object). Since 3.5, you can annotate functions and variables with type hints. The runtime ignores them; external tools (mypy, pyright) enforce them. Think of it like TypeScript for Python, except the community adopted it later and adoption is still uneven across libraries.

Start here

  • Real Python: Type Checking Guide — comprehensive tutorial on type hints, from basics to generics. The best single resource
  • typing module docs — reference for Optional, Union, TypedDict, Protocol, generics
  • mypy Getting Started — how to run the type checker, configure strict mode, interpret errors

Pydantic (Python's Zod)

  • Pydantic Models — define a class, get validation, serialization, and JSON schema for free. This is what replaces z.object() in Python land
  • Pydantic Types — constrained types, custom validators, computed fields
  • Pydantic Serialization — model_dump(), model_dump_json(), custom serializers

dataclasses (lightweight alternative)

  • dataclasses module — like Pydantic but without validation. Use for internal data structures where you control the input. Think of it as a typed interface that also generates __init__, __eq__, and __repr__

TypeScript ↔ Python type mapping

  • string → str
  • number → int or float (Python distinguishes them)
  • boolean → bool
  • string | null → str | None (or Optional[str])
  • string[] → list[str]
  • Record<string, number> → dict[str, int]
  • { name: string; age: number } → TypedDict or Pydantic model
  • interface → Protocol (structural typing) or ABC (nominal)
  • enum → enum.Enum or Literal["a", "b", "c"]

Async Python

Python's async model is conceptually identical to Node's: single-threaded event loop, async/await keywords, non-blocking I/O. The difference is that Python was synchronous for 25 years before asyncio arrived, so the ecosystem is split. Some libraries are sync-only, some are async-only, some offer both. FastAPI uses async by default, which is why this matters.

Start here

  • Real Python: Async IO Guide — the best intro. Covers asyncio.run(), await, asyncio.gather(), and when to use async vs sync
  • asyncio docs — official reference. Dense but complete

Key differences from Node

  • Node is async by default; Python is sync by default. You opt in with async def.
  • Node's event loop runs automatically; Python's requires asyncio.run() to start.
  • Promise.all() → asyncio.gather()
  • setTimeout() → asyncio.sleep()
  • No equivalent of Node's callback pattern. Python went straight from threads to async/await.
  • The GIL (Global Interpreter Lock) means CPU-bound work doesn't parallelize across threads. Use multiprocessing or concurrent.futures.ProcessPoolExecutor for CPU parallelism.

Ecosystem: pip, venv, project setup

The Python packaging ecosystem is more fragmented than Node's. There's no single npm equivalent; you'll encounter pip, poetry, uv, pdm, and conda. For new projects, uv (from the ruff/astral team) is the modern choice. For existing projects, follow whatever they already use.

Package management

  • uv — fast Python package manager (written in Rust). Handles venvs, dependencies, and Python version management in one tool. The pnpm of Python. Start here for new projects
  • pip basics — the default package manager. pip install requests is npm install axios
  • venv — virtual environments isolate dependencies per project. python -m venv .venv then .venv/Scripts/activate. Think of it as a scoped node_modules

npm ↔ Python tooling map

  • package.json → pyproject.toml
  • node_modules/ → .venv/
  • npm install → uv sync or pip install -r requirements.txt
  • npx → uvx or pipx run
  • nvm → uv python or pyenv
  • eslint → ruff (linter + formatter, very fast)
  • prettier → ruff format or black
  • tsc --noEmit → mypy or pyright

Project structure

  • uv Project Guide — creating and managing Python projects with uv
  • Python Packaging Tutorial — pyproject.toml, src layout, building distributions

Testing with pytest

pytest is Python's Jest. It discovers test files automatically, has a fixture system (like beforeEach but more powerful), and supports parametrized tests for covering many cases with minimal boilerplate.

Start here

  • pytest Getting Started — write your first test in 2 minutes
  • pytest Fixtures — dependency injection for tests. This is the key concept that makes pytest different from unittest
  • pytest Parametrize — run the same test with 20 different inputs. Essential for testing classification logic

Jest ↔ pytest mapping

  • describe/it → plain functions named test_*() in files named test_*.py
  • expect(x).toBe(y) → assert x == y (plain Python asserts, pytest rewrites them for good error messages)
  • beforeEach → @pytest.fixture
  • jest.mock() → unittest.mock.patch() or monkeypatch fixture
  • test.each → @pytest.mark.parametrize
  • npm test → pytest (auto-discovers all test files)
