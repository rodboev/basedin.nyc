Recommended Hierarchy

1. Lead with harness engineering

Use language around agent loops, orchestration, routing, verification, feedback handling, and durable execution. This is the most differentiated layer and the one the updated target list reinforces most clearly.

2. Support with memory expertise

Keep mcp-memory-service and claude-mem in the story, but treat them as evidence that you understand a critical subsystem, not as the entire identity.

3. Close with production delivery

Fortune 500 work, Liberty Notes AI, Liberty Scheduling, and Shopify/WordPress results prove this is not speculative architecture. You ship operating systems for real teams and real revenue.

Usable Copy

Headline options

  • AI Harness Engineer building agent loops, workflow control planes, and production web systems.
  • Full-stack engineer specializing in agent orchestration, memory systems, and AI-integrated applications.
  • Open-source contributor and maintainer focused on agent loops, memory infrastructure, and durable execution.

Short positioning lines

  • I build the execution layer around models: routing, review, retries, checkpoints, and real delivery.
  • My edge is not prompting. It is designing loops that make model output survivable in production.
  • I work where memory, orchestration, and shipping code intersect.

Keep vs De-emphasize

Keep

  • pr-sweep as a concrete harness, not just an OSS vanity project.
  • agent-peer-review as proof that you think in adversarial validation loops.
  • Memory maintainership as subsystem depth.
  • Liberty Notes AI and Liberty Scheduling as proof of production constraints.

De-emphasize

  • Generic “AI integration” language when a loop or harness term would be more precise.
  • Memory as the sole identity.
  • Hypey “next wave” language.
  • Claims about autonomy without the maintainership, CI, and shipped-PR evidence right next to them.
