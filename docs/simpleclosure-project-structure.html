SimpleClosure: Project Structure

Architecture, PR history, and file-by-file breakdown of the TMDB take-home at github.com/rodboev/simpleclosure.

Sections

How the app works

A movie discovery app built on Next.js 16. The server fetches 20 movies from TMDB's /discover/movie endpoint, normalizes them into app types, and sends rendered HTML to the browser. The client shows a responsive poster grid with genre filtering (round-trips to the server) and sort controls (reorders locally, no network). A hover/focus overlay reveals each movie's overview. The whole thing runs dark because poster art is composed for dark backgrounds.

Request lifecycle

  1. Browser requests /?genre=science-fiction
  2. page.tsx (server component) resolves the slug to a TMDB genre id
  3. tmdb.ts fetches /discover/movie?with_genres=878&api_key=... and maps raw results to Movie[]
  4. page.tsx passes normalized movies, genres, and the selected slug to DiscoverView
  5. DiscoverView (client component) sorts the array in state and renders through MovieGrid → MovieCard
  6. Genre change: router.push inside startTransition, server refetches, grid dims during the wait
  7. Sort change: local useState flip, array re-sorted from props, zero network

Data flow in MVC terms

Modeltmdb.tsOwns all data access and normalization. Talks to the external API, maps responses into Movie and Genre types. The only file that knows TMDB's field names.
Controllerpage.tsxReceives the request (URL search params), calls the model, resolves and redirects non-canonical URLs, passes clean data to the view.
ViewDiscoverView, MovieGrid, MovieCardReceives typed props and renders. DiscoverView owns the sort state and genre navigation; the grid and cards are stateless.

Architectural layers

Data layer: src/lib/tmdb.ts

Server-only. Imports server-only on line 1, which makes any client-side import a build error. Contains:

  • Type definitions: Movie (the app's normalized shape), Genre (id + name + slug), RawMovie (what TMDB actually sends, all fields optional except id)
  • tmdbFetch<T>: generic fetcher that reads the API key from process.env, constructs the URL, throws on missing key or non-OK response
  • mapMovie: normalizes one raw TMDB result into a Movie. Defaults absent titles to "Untitled", absent ratings/vote counts to 0, empty strings and nulls are distinguished (releaseDate: raw.release_date || null)
  • posterUrl: builds a full image URL from a poster path, returns null for missing posters. Exported because tests use it
  • fetchDiscover: fetches one page of movies, optionally filtered by genre id
  • fetchGenres: fetches the genre list, slugifies each name, deduplicates collisions by appending the genre id. Caches for 24 hours via { next: { revalidate: 86400 } }
  • slugify: lowercases, replaces non-alphanumeric runs with hyphens, trims leading/trailing hyphens

The boundary is greppable: searching src for poster_path, vote_average, or image.tmdb.org hits only this file, its tests, and the captured fixtures.

Logic layer: src/lib/sort.ts

A pure function. Takes Movie[], a sort key ("rating" or "releaseDate"), and a direction. Returns a new sorted array. Fourteen lines. Three behaviors beyond basic sorting:

  • Copies before sorting: [...movies].sort(). In-place sort returns the same reference; React skips the re-render.
  • Ties break by vote count descending. Two movies rated 6.4: the one with 4,000 votes ranks above the one with 900.
  • Null release dates sink to the bottom regardless of sort direction.

Page layer: src/app/page.tsx

An async server component. Does three things:

  1. Reads searchParams.genre from the URL
  2. Resolves it through resolveGenre: matches a slug against the fetched genre list, falls back to the default genre (sci-fi, id 878), and redirects anything non-canonical (numeric ids, case variants, repeated params, bare /) to the canonical slug URL
  3. Fetches movies for the resolved genre and renders DiscoverView

Component layer

DiscoverView.tsx is the only "use client" component in the app besides error.tsx. It owns:

  • Genre <select> that navigates via router.push inside a useTransition
  • Sort key <select> and direction toggle button, both in useState
  • Pending state: dims the grid to 50% opacity with aria-busy during genre refetch
  • Calls sortMovies on every render with the current key/direction

MovieGrid.tsx is stateless. Renders an <ul> of MovieCards, or an empty-state message if the array is empty. Grid layout: 2 columns below 500px, 3 columns at 500px, auto-fill with 9rem minimum above 640px.

MovieCard.tsx is stateless. One <li> per movie:

  • Poster via next/image with responsive sizes, or a styled placeholder for null posters (role="img" with aria-label)
  • Color-coded rating badge: emerald at 7+, amber 5-6.9, red below 5. Hidden when voteCount === 0.
  • Hover/focus overlay with blurred scrim showing the overview, clamped to 9 lines
  • Lift animation on hover/focus, respects prefers-reduced-motion
  • Title (never truncated) and release year below the poster

Shell

  • layout.tsx: Geist Sans and Geist Mono fonts, dark body (bg-zinc-950 text-zinc-100), antialiased
  • globals.css: Tailwind v4 import, dark color-scheme, font-family set to the Geist variable
  • loading.tsx: pulse-animated skeleton matching the grid layout. Shows on initial cold load only; genre switches keep the current page visible.
  • error.tsx: client component with a retry button. tmdbFetch throws on non-OK responses; Next's error boundary catches it here.

File-by-file details

src/lib/tmdb.ts (102 lines)

The model. Every TMDB interaction goes through this file.

  • Lines 1: import "server-only". A build-time constraint: if a client component imports this file, the build fails. Without it, process.env.TMDB_API_KEY would be undefined on the client (env vars without the NEXT_PUBLIC_ prefix aren't exposed), and the fetch would fail with a confusing runtime error. This makes it a compile error instead.
  • Lines 7-21: Three type definitions. Movie is the app's type; all seven fields have explicit types (no optional fields, nulls are explicit). Genre adds a slug field that TMDB doesn't have. RawMovie mirrors TMDB's response shape with everything optional except id.
  • Lines 33-35: posterUrl(). Builds https://image.tmdb.org/t/p/w342/path.jpg from a poster path, or returns null. Exported for testing.
  • Lines 37-47: mapMovie(). The normalization function. Uses ?? for null/undefined defaults and || for empty-string-to-null conversion on releaseDate. The distinction matters: overview ?? "" keeps an empty string as-is but catches undefined; release_date || null treats both empty string and absent as null.
  • Lines 49-68: tmdbFetch<T>(). Generic fetcher. Throws before the request if the API key is empty, and after if the response is non-OK. Accepts RequestInit for passing cache directives.
  • Lines 70-77: fetchDiscover(). Adds with_genres only when a genre id is provided (null means "all genres"). Returns mapped Movie[].
  • Lines 79-84: slugify(). Private. Lowercases, replaces non-alphanumeric runs with hyphens, trims edge hyphens.
  • Lines 86-102: fetchGenres(). Fetches the genre list, slugifies each name, deduplicates collisions with a Set. Falls back to the numeric id for names with no alphanumeric characters. The revalidate: 86400 caches the genre list for a day.

src/lib/sort.ts (18 lines)

A pure function with no imports beyond the Movie type.

  • Exports SortKey ("rating" | "releaseDate") and SortDir ("asc" | "desc") as types so the view doesn't hardcode string literals.
  • The comparator handles rating sort and date sort in one function via a key parameter. A flip multiplier reverses direction.
  • Rating ties break by b.voteCount - a.voteCount (higher confidence first, regardless of sort direction).
  • Date sort: null dates go last via explicit null checks. Equal dates break by vote count. String comparison (<) works because TMDB dates are ISO format (YYYY-MM-DD).
  • Returns [...movies].sort(): the spread copy is the entire reason this is its own function rather than an inline sort in the component.

src/app/page.tsx (45 lines)

The controller. An async server component.

  • resolveGenre(): takes the raw searchParams.genre (could be a string, an array, or undefined) and returns a Genre | null. Handles every degenerate input: arrays (takes the first element), numeric ids (looks up by id and redirects to the slug), case variants (lowercases before matching), "all" (returns null, meaning no genre filter), bare / or unknown values (redirects to the default genre). Every non-canonical path ends in a redirect() call.
  • Home(): awaits searchParams (a Promise in Next 16), fetches genres and movies, renders the heading and DiscoverView. The await searchParams is new in Next 16; previous versions passed params as a plain object.

src/components/DiscoverView.tsx (62 lines)

The only interactive client component. Receives movies, genres, and selectedGenre as props from the server.

  • Genre select: controlled by the selectedGenre prop from the URL. onChange calls router.push inside startTransition. This triggers a server re-render; the grid dims to 50% via isPending.
  • Sort controls: sortKey and sortDir in useState. Changing the sort property resets direction to descending. The direction button toggles asc/desc with an arrow character and a descriptive aria-label.
  • Render: calls sortMovies(movies, sortKey, sortDir) on every render (no memoization; sorting 20 items is sub-millisecond). Passes the result to MovieGrid.

src/components/MovieGrid.tsx (16 lines)

Stateless. If movies.length === 0, renders "No movies matched this filter." Otherwise renders a <ul> with responsive grid classes: grid-cols-2 → grid-cols-3 at 500px → auto-fill minmax(9rem) at 640px.

src/components/MovieCard.tsx (68 lines)

Stateless. Each card is an <li> with tabIndex={0} for keyboard focus.

  • Poster: next/image with fill layout and responsive sizes (45vw on phones, 30vw on tablets, 220px on desktop). Null posters render a <div role="img"> with the movie title as placeholder text.
  • Rating badge: positioned top-right with absolute. Color set by ratingTone(): >= 7 is emerald, >= 5 is amber, below 5 is red. Uses Tailwind color classes, not inline styles. Hidden entirely when voteCount is 0. A data-tone attribute makes the threshold testable.
  • Overlay: absolute -inset-1 (extends 1px past the card to avoid rounding gaps). bg-linear-to-t gradient from 85% opacity to 50% with backdrop-blur-sm. Opacity transitions on hover and focus. motion-safe: prefix respects reduced motion. Overview text clamped to 9 lines.
  • Title/year: title is an <h2> (never truncated). Year extracted with releaseDate?.slice(0, 4); omitted when null.
  • Lift: -translate-y-1 on hover/focus. Also motion-safe: gated.
  • Touch: touch-manipulation removes the 300ms delay on mobile. Post-merge commit dadb5ab added click-to-show for the overlay on iPhone (no hover event on touch devices).

src/app/error.tsx (15 lines)

Client component (required for error boundaries). Shows "Something went wrong" with a retry button that calls reset(). Catches throws from tmdbFetch: missing API key, non-OK response, network failure.

src/app/loading.tsx (17 lines)

Route-level Suspense boundary. Renders pulse-animated skeleton cards matching the grid layout (20 placeholder cards). Shows on initial cold load only; once the page is hydrated, genre switches go through useTransition and the skeleton never re-appears.

src/app/layout.tsx (16 lines)

Root layout. Loads Geist Sans and Geist Mono via next/font/google. Sets the body to bg-zinc-950 text-zinc-100 with min-h-full flex flex-col so the error/loading states can center vertically. Metadata: "Movie Discovery" title, description for Open Graph.

src/app/globals.css (12 lines)

Tailwind v4 setup: @import "tailwindcss" and an @theme inline block mapping --font-sans and --font-mono to the Geist CSS variables. Sets color-scheme: dark on html.

Test helpers

src/test/data.ts: a throughDataLayer function that stubs fetch with a fixture, runs it through the real fetchDiscover/fetchGenres, and unstubs. This means component tests consume movies that have been through mapMovie, not hand-built objects. If the mapper changes, every component test picks up the new shape automatically.

src/test/server-only.ts: a no-op module that Vitest aliases in place of the real server-only package. The real package throws outside a React Server environment, which is correct in the app build and wrong in a test runner.

src/test/setup.ts: imports @testing-library/jest-dom/vitest for matchers like toBeInTheDocument() and toHaveAttribute().

Mocking strategy

fetch is replaced globally via vi.stubGlobal("fetch", mock) with a vi.fn() that returns the fixture. afterEach calls vi.unstubAllGlobals() to restore it. Mocking is at the network boundary; everything above (tmdbFetch, mapMovie, fetchDiscover) runs for real. DiscoverView.test.tsx mocks next/navigation via vi.mock to capture router.push calls.

Configuration

next.config.ts

Two settings: images.remotePatterns allows image.tmdb.org/t/p/** through the image optimizer, and logging.fetches.fullUrl prints full fetch URLs in the dev server terminal (helpful for verifying that with_genres and api_key params are set correctly).

vitest.config.ts

Three important settings: @vitejs/plugin-react for JSX transforms in tests, a resolve.alias that maps server-only to the no-op stub and @ to src/, and test.environment: "node" as the default (component tests override with // @vitest-environment jsdom per-file).

tsconfig.json

strict: true, jsx: "react-jsx", moduleResolution: "bundler". Path alias @/* maps to ./src/*. Targets ES2017.

.env

Contains the TMDB API key in plaintext. Committed intentionally: the key came in plaintext with the assignment, it's free-tier, and requiring manual env setup would break the zero-setup contract. No NEXT_PUBLIC_ prefix, so it stays server-side.
